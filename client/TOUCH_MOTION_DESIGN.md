# 智慧伴学触屏动效设计

状态：已接入 ArkUI 客户端（2026-09-20）。保留 HTML 预览用于对照，不把浏览器演示当作原生实现。

HTML 预览仅用于早期审核节奏和层次，相关临时产物已在原生实现完成后清理。

## 设计依据与现状

依据用户保存的华为《动效属性》（页面更新时间 2026-08-10）：
https://developer.huawei.com/consumer/cn/doc/design-guides/animation-attributes-0000001797117229

正文说明：时长应随复杂度、运动范围变化；标准曲线用于视线内状态切换，减速曲线用于入场，加速曲线用于退场；弹簧支持打断、继承速度及自然时长。文档举例为颜色变化 100ms、开关 150ms、局部列表变化 200ms、全屏图片 350ms。这些是示例，不是所有按钮的强制参数。

接入前检查：主页已有 HDS pressShadow/pointLight，但旧手势处理存在 Move 提前结束、Cancel 未清理的问题；多个页面混用独立进场动画、持续呼吸和延时导航。本次改用原生按压状态，取消重复进场与装饰性呼吸，导航不等待动画结束。

## 保留的视觉语言

- 冰蓝底色 `#ECF4FC`、冷白材质 `#F6FBFF`、深蓝主操作 `#155AA5`、深墨正文 `#173A56`、次级文字 `#526D83`、边界 `#D7E5F2`。
- 使用系统 HarmonyOS 字体；按钮主标签 14–16vp，中等或半粗，不随按压改变字重。
- 沿用现有胶囊导航、16vp 按钮及 24vp 卡片圆角，不改页面信息层级。文案在按钮内居中；课程卡片正文左对齐。
- 触感重点放在主操作与课程入口：轻压、降低悬浮感、局部边缘受光。读题、记录与讨论内容保持稳定。

## 按钮类型与参数

以下是当前客户端参数，仍需真机体验后微调。弹簧响应值不是固定动画时长。

| 控件 / 示例 | 按下反馈 | 松手 / 选中反馈 |
|---|---|---|
| 主按钮：查看课程、AI 出题、提交、创建小组 | 100ms，缩至 0.972，下沉 1vp；主页保留原有 HDS 按压光影 | 响应 0.30、阻尼比 0.86、叠加时长 0.12 的恢复；有效点击立即执行 |
| 次按钮：保存、导出、设置 | 沿用统一轻压参数，不额外添加光影层 | 同一高阻尼恢复，无反复弹跳 |
| 图标式入口 | 独立图标反馈缩至 0.95；已有 Button 默认采用 0.972 | 保留现有命中区域与点击语义 |
| 大卡片：课程、课次、笔记入口 | 不缩放宽大表面，仅下沉 1vp | 高阻尼恢复，手机和平板位移相同 |
| 导航 / 模式切换 | 标签仅轻压；有效点击立刻更新选中状态 | 底板 220ms 标准曲线移动；连续点击从当前状态转向新位置 |
| 题目选项 | 不移动正文；边框与底色 120ms 变化 | 保留原选中标记和正误逻辑；已提交选项禁用，不产生假反馈 |
| 删除、结束讨论 | 统一轻压反馈 | 保留既有确认和异步处理，不修改删除逻辑或额外添加移除动画 |

标准曲线采用文档的 `cubic-bezier(0.4,0,0.2,1)`；内容短暂淡入用 `cubic-bezier(0,0,0.2,1)`。主按钮弹簧取值弱于文档 Response 0.555 / DampingFraction 0.53 的示范，以适合长期学习。

## 完整触摸周期

1. 原生 `stateStyles` 的 pressed 状态开始反馈，不在 Down 触发业务操作。
2. 移动、离开控件、滚动竞争与取消交由 ArkUI 的原生状态机处理，不使用 HTML 的 8px 阈值模拟鸿蒙手势。
3. Up 内的有效点击立即执行操作，同时恢复外观，不等动画播放完毕。
4. Cancel / 切后台 / 页面销毁必须清理指针和动效，不留下缩小状态。
5. 连续点击允许动效改变目标、保留速度；出题、保存、发送等异步操作按原业务规则阻止重复请求。
6. 长按沿用实际控件语义，不增加菜单或人工 650ms 点击阈值。HTML 的阈值仅属于演示。

## 加载、结果和无障碍

- 加载保持按钮占位、文字与图标布局稳定。进入真实等待状态才展示原生等待指示；不添加人为等待时间。
- 保存成功、出题完成采用明确文字与小图标反馈，不以动画代替结果。失败说明原因并恢复重试能力。
- 刷题正误同时使用文字与标记表达，颜色作为辅助；统计立即刷新，不使用数字滚动影响读取。
- 设置 → 界面动效 → 减弱动效：关闭新增位移、缩放、弹性及导航动画；选中状态、原生按压颜色与业务反馈保留。通过应用私有 Preferences 保存，与材质强度分开，不修改系统设置，也不声称已自动跟随系统减弱动效。
- 不自动启用震动、声音，不加入持续呼吸、扫光、漂浮。AI 入口仅在用户触碰时回应。
- 焦点环、键盘及辅助触控路径保留。缩放仅作用于视觉内容，不缩小实际命中区域。

## 页面切换

- 同级页签：底板 220ms 标准曲线平移，内容 120ms 从 0.65 淡入，和 HTML 预览保持同一节奏；不把整页来回滑动。
- 课程库 → 学习空间 → 工作台，笔记入口 → 列表 → 编辑：240ms、22vp 短距离进入，返回方向相反。
- 课堂详情、AI 对话/历史、刷题内部页签、学习小组的聊天/总结区域分别使用持续存在的容器，不因动画重新创建业务状态。
- 课程详情、笔记创建类型、课表课程列表：220–240ms 淡入配合 18–24vp 位移；设置从右侧短距离进入。
- 连点会清理待执行的旧动画任务；页面销毁清理定时器。业务切换立即发生，不为动画延迟请求、保存或返回。
- 内容宿主只呈现新目标的过渡，不在离开后保留另一个可交互的旧页面；没有添加系统路由或返回手势。

## 原生落地位置与验证

`common/TouchMotion.ets` 集中参数；页面使用 `stateStyles`，而不是 `AttributeModifier.animation`。后者在模拟器上会抛出 `Method not implemented`，已通过运行日志定位并替换，参见[华为官方接口说明](https://developer.huawei.com/consumer/cn/doc/doccenter-dev-faq/faqs-arkui-1523)。`common/components/MotionPage.ets` 管理内容切换，`MobileTabs.ets` 管理导航底板，`service/MotionPreferences.ets` 保存偏好。

覆盖学生/教师客户端的共用按钮及主要课程、课次、笔记卡片。保留原有 HDS 支持判断、材质回退和教师端配色。本次未修改服务端、角色权限、数据结构或系统设置。

已验证：ArkTS 编译；8 项动效控制测试和10项既有录音生命周期测试通过；连接的平板模拟器完成课程库、课程详情、课程、刷题、笔记列表/创建类型、AI 学习小组与设置的导航检查。减弱动效开关通过强制停止/重新启动后的保存检查，验证后恢复完整动效。测试只查看现有数据，不创建笔记、发送消息或调用 AI 出题。

原生截图位于 `.codex-run/native-motion-check/`。分帧截图包含工具延迟，只能辅助检查状态，不能用于报告流畅帧率。仍需手机模拟器/真机验证多指、后台中断、分屏、真实 GPU 帧率与完整异步业务链路。

另外已在平板验证“加入课程”按钮按住缩小、松开恢复；拖动离开按钮没有误打开表单。对比图为 `press-comparison.png`。测试使用项目已有工具，没有安装依赖。

单元测试依赖已有鸿蒙 SDK 的 TypeScript：将 `RECORDING_TEST_TYPESCRIPT` 指向 SDK 的 `openharmony/ets/build-tools/ets-loader/node_modules/typescript`，用现有 Node 执行 `node --test client/tests/touch-motion.test.cjs client/tests/recording-lifecycle.test.cjs`。

本次设计根据 frontend-design 技能收敛为用户主动触发的反馈，保留既有品牌与布局，把视觉强调集中在主按钮和课程入口。

先前 HTML 预览验证：1440px 与 390px 宽度无横向溢出；导航、选项、加载、Cancel 恢复、减弱动效通过，临时预览与截图现已清理。本次另外安装了原生客户端进行检查，没有后端数据写入。
